# MCO – методи багатокритеріальної оптимізації

**MCO** – Multi-Criteria Optimization, багатокритеріальна оптимізація. Вебзастосунок для лабораторних
робіт 12–13: вибір найкращої альтернативи з таблиці (ноутбуки, смартфони, каталоги інтернет-магазинів)
і розв’язування неперервних задач, заданих формулами.

* **Фронтенд** – React 19 + Vite, React Router; графіки – власні SVG-компоненти. Інтерфейс зроблено за
  макетом «MCO Studio – редизайн».
* **Бекенд** – FastAPI над бібліотекою `mco` (`backend/`): 10 методів дискретного вибору, 6 способів
  визначення ваг, 5 методів для неперервних задач, 4 способи побудови фронту Парето (зокрема власний
  NSGA-II), парсери каталогів Brain, Telemart і Rozetka.

## Запуск для розробки

Потрібні Node.js 20+ і Python 3.11+.

```bash
# 1. Бекенд
cd backend
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn api.main:app --reload --port 8000
```

```bash
# 2. Фронтенд (в іншому терміналі, з кореня проєкту)
npm install
npm run dev                       # http://localhost:5173, запити /api проксуються на :8000
```

Документація API (Swagger): http://localhost:8000/docs

## Запуск однією командою (зібрана версія)

```bash
npm run build                     # збирає фронтенд у dist/
```

## Екрани

| Маршрут | Що робить |
|---|---|
| `/discrete/data` | джерело альтернатив: приклади, інтернет-магазин (Brain, Telemart – з сайту; Rozetka – збережена сторінка), власний CSV/Excel/HTML |
| `/discrete/criteria` | критерії (напрям, вага), ваги вручну / рівні / AHP / ентропія / CRITIC / ROC |
| `/discrete/limits` | умови на альтернативи (≤, ≥, «у списку», «містить» …), кількість допустимих, причини виключення, обробка пропусків |
| `/discrete/solution` | вибір методу та його параметрів, рекомендація, рейтинг, множина Парето на площині, внесок критеріїв, експорт CSV/JSON |
| `/discrete/compare` | порівняння методів: місця, бали Борда, кореляція Спірмена, час |
| `/discrete/sensitivity` | чутливість до ваги критерію, стохастичний аналіз Монте-Карло |
| `/continuous` | модель формулами, компроміс вибраним методом, фронт Парето (NSGA-II – фоновою задачею з прогресом і збіжністю) |
| `/help` | інструкція користувача та опис методів |

## API (основне)

| Метод | Шлях | Призначення |
|---|---|---|
| GET | `/api/methods` | реєстр методів з описом параметрів (за ним будуються форми) |
| GET | `/api/datasets`, `/api/datasets/{id}` | вбудовані набори даних |
| POST | `/api/upload` | CSV, Excel або збережена сторінка каталогу (HTML) |
| POST | `/api/weights/{equal\|manual\|ahp\|entropy\|critic\|roc}` | ваги критеріїв (для AHP – з CR) |
| POST | `/api/discrete/solve`, `/compare`, `/sensitivity`, `/montecarlo`, `/feasibility` | дискретний вибір |
| POST | `/api/continuous/analyze`, `/solve`, `/front` | неперервні задачі |
| POST | `/api/jobs/front`, `/api/jobs/shops/{shop}`; GET `/api/jobs/{id}` | фонові задачі з прогресом |

Сервер не зберігає стан: клієнт щоразу надсилає всю постановку. Помилки введення повертаються як 422 з
повідомленням українською. Формули неперервних задач перевіряються до розбору: дозволено лише числа,
оператори, дужки, змінні задачі та функції sin, cos, exp, log, sqrt, abs тощо.

## Дані з інтернет-магазинів

Завантажувач читає `robots.txt`, робить не більше одного запиту за 2 с, чесно називає себе в
User-Agent і кешує сторінки на добу (`backend/data/cache/`). Rozetka закриває каталог перевіркою
браузера для автоматичних запитів, і програма її не обходить: збережіть сторінку каталогу в браузері
(Ctrl+S → «Веб-сторінка, лише HTML») і завантажте файл.
